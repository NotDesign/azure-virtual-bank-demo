# Public reference exchange rates

The HTML Demo reads `GET https://api.coinbase.com/v2/exchange-rates?currency=USD`. It sends no API key, authorization, customer identifier, wallet address, or credentials. Coinbase documents this endpoint as requiring no authentication: [official exchange-rates documentation](https://docs.cdp.coinbase.com/coinbase-app/track-apis/exchange-rates).

The response is `{ "data": { "currency": "USD", "rates": { "USD": "1.0", "HKD": "…", "USDT": "…" } } }`. Each value is units of that currency for **one USD**. The module validates the USD base, its unit rate, and every returned value as positive and finite before replacing the last successful snapshot. Cross rates use `rates[to] / rates[from]`. Missing assets return `null`, including a missing CNH rate; CNY is never substituted. USDT uses its supplied market rate rather than assumed dollar parity.

On 2026-11-10, the public endpoint returned HTTP 200 with `Access-Control-Allow-Origin: *` and `Cache-Control: no-store`. USD, HKD, EUR, SGD, CNY and USDT were present; CNH was absent. Neither the documented schema nor this response supplies a quote timestamp or guarantees new market data every 30 seconds. The UI therefore labels `fetchedAt` as the local retrieval time, and calls the prices reference rates. Every-30-second **polling is an application schedule**, not a provider freshness guarantee. CORS and availability can change.

## Runtime API

`window.AzureMarketRates` exposes:

- `ready: true` after installation.
- `status()` returns a copied `ratesUSDBase` map plus `provider`, `endpoint`, `base`, `fetchedAt`, `attemptedAt`, `nextRefreshAt`, `ageMs`, `hasData`, `loading`, `stale`, `error`, `failures`, `paused`, `stopped`, `phase`, and `refreshIntervalMs`.
- `getRate(from, to)` returns a cross rate, or `null` if either currency is unavailable. Even an unavailable currency converted to itself returns `null`.
- `refresh()` returns the current request promise; overlapping calls share one request. Manual refresh respects an HTTP 429 cooldown.
- `subscribe(fn)` immediately calls `fn(status())` and returns an unsubscribe function. Later notifications do not render the application.
- `stop()` aborts a request and stops polling. An explicit later `refresh()` resumes it.

One feed lives on the highest accessible same-origin window. Active customer `home`, `accounts`, `fx`, and `wallets` pages lease this feed; HQ customer iframes share the public snapshot without putting any customer information in it. HQ's own administrative pages do not initiate automatic polling. Hidden documents pause and abort requests; visibility restoration fetches again. Removing a customer iframe releases its lease.

The interval starts after each request finishes. Requests abort after 8 seconds. Failed or invalid responses retain the last successful snapshot; the UI marks it stale. With no successful snapshot, prices remain unavailable, not fabricated. HTTP 429 uses a local exponential backoff of 60, 120, 240, then at most 300 seconds. When the response exposes a valid `Retry-After` header to browser JavaScript, its longer requested delay takes precedence, even beyond 300 seconds. Manual refresh and visibility restoration cannot shorten this provider cooldown. Without an accessible valid header, the module uses the local backoff. Other failures retry after 30 seconds while a relevant view is visible. A retained snapshot also becomes stale after 60 seconds without successful retrieval.

`market-rates.js` updates only its panel, countdown, and the FX market-reference caption. It never writes `FXR`, `BALANCES`, transaction ledgers, or form trade quotes, and never calls the application's full render from a rate callback. The existing seeded FX chart is explicitly labeled illustrative. The original Demo execution basis is separately identified, and the old fixed “30 seconds” text is replaced by a simulated/not-price-locked execution-mode label. This is no bank or exchange order integration.

Both the outer page and the CMS CSP must allow `connect-src https://api.coinbase.com` because the shared feed fetches from its top same-origin host. Keep other CSP directives and the exact provider allowlist. The module needs no signup, paid service, or account access.

## Verification

Run `node scripts/verify-market-rates.mjs`. `DEMO_URL` selects another local or deployed Demo root; `QA_REPORT` overrides the JSON output path. The focused verifier mocks deterministic snapshots and time for scheduling, conversions, validation, stale/error states, rate limits, visibility, shared HQ/customer feeds, and form/modal preservation. A separate real CORS smoke fetch checks only public response access and schema; it does not assert that rates are executable or freshly generated by the provider.


## Other integration options checked on 2026-11-10

| Provider | Authentication | Provider refresh | Fit |
| --- | --- | --- | --- |
| Coinbase Exchange Rates | No authentication for this endpoint | No precise update interval or quote timestamp promised in the endpoint documentation | The current browser Demo uses its public fiat/USDT reference snapshot; 30 seconds is the app polling interval. |
| currencyapi | API key | Daily on Free, hourly on Small, every 60 seconds from Medium | A keyed alternative with `meta.last_updated_at`; use a server-side proxy/cache for private keys. Polling it every 30 seconds would not make its 60-second source refresh faster. |
| OANDA v20 Pricing | Account ID and bearer token | Pricing stream supplies at most 4 prices per second per requested instrument | An authenticated option when a declared sub-minute fiat feed is required. Instrument availability, access and display rights need confirmation; it is not enabled in this Demo and does not provide the USDT wallet integration. |
